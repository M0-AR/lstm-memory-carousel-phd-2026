Across 1,000 Fillers?

The whole story in three sentences. (1) A plain recurrent network multiplies its memory every step, so the lesson from 50 steps ago shrinks to 8×10⁻¹⁵ of itself — training hears nothing. (2) Adding instead of multiplying (the “constant error carousel”) keeps the lesson at full size, and a gate that starts nearly shut stops noise from burying it. (3) A second gate that starts nearly open lets the network forget on purpose — and one gate doing both jobs (the GRU idea) can hold a 300-step lesson across 3,000 steps.

🌱 Beginner guide — read this and you are a professional

After this section you will know more than most interview candidates. Let’s work this out in a step-by-step way to be sure we have the right answer.

  1. Step 1 — The game. The network sees one row: a letter (A–H), then N meaningless filler symbols, then one question: which letter was first? It reads left to right, one symbol per step, and between steps it may carry only 32 numbers (its memory). Before the first symbol, all 32 are zero.
  2. Step 2 — One step, slowly. Letter B arrives. B picks its row from a table (16 rows × 32 numbers). The old 32 numbers each get multiplied by table numbers and added up (that’s a matrix multiply). Add B’s row. Squeeze everything between −1 and 1 (that’s tanh). Done — that’s the new memory. Same two tables every step: this looping is why it’s called recurrent.
  3. Step 3 — Learning means blame. After the answer, a message (the learning signal) travels backward, telling each step’s tables how to change. Going back through a step multiplies the signal by that step’s factor. Measured here: ≈0.52 per step. After 10 steps 0.52¹⁰ ≈ 0.0014 — under 1% survives. The letter is 50 steps back, so its signal is ≈10⁻¹⁴. The tables hear nothing. That is the vanishing gradient — not a metaphor, a measured number (see chart above).
  4. Step 4 — The fix, part 1: add, don’t multiply. Give the network a second memory (the cell). New values are added to it: cell = cell + new. Backward through a plus sign, the signal keeps its size exactly (factor 1.00) — the “constant error carousel”. Suddenly 50-step lessons arrive intact.
  5. Step 5 — The fix, part 2: doors. A gate is a number between 0 and 1 that multiplies what passes: 0 = shut, 1 = open. The input gate starts nearly shut (bias −4 → 1.8% open), so fillers barely write. The forget gate starts nearly open (bias +3 → 95%), so old content stays until the network chooses to wipe it. One gate doing both (keep 90% old + write 10% new) can never pile up — that’s the GRU idea, and it generalises 10× past its training length.
  6. Step 6 — Why bigger tables don’t save you. Starting tables 4× larger flips decay into explosion (×1.196/step → ×7,760 over 50 steps — one update throws the tables across the room). 2× looks perfect (0.978) but training moves the tables, so the factor drifts. Only structure (the plus sign) holds 1.0. Clipping (scaling oversized signals down) cures explosions, never shrinkage.
  7. Step 7 — Prove it on reality. The same five networks are tested on live Bitcoin data: the first day’s market “mood” must be recalled after N noisy days. Gated networks win; and the raw market turns out easier than random fillers (real noise has patterns to cheat with) — so honest benchmarks always keep the random-filler control next to the real-data test. That discipline is built into this repo.

Interview-ready one-liners: “Vanishing gradient = per-step Jacobian factor below 1, compounding exponentially.” · “LSTM’s carousel is a plus sign, so error flows unchanged.” · “Gate biases are initial conditions, not trivia: input-shut, forget-open.” · “GRU’s convex mix bounds the state, which is why it extrapolates in length.”
